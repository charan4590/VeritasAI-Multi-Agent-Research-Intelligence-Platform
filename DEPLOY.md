# Deployment Guide

Three supported platforms, roughly in order of setup simplicity: **Render**
(zero-config via `render.yaml`), **Railway** (near-zero-config, great free
tier for demos), and **Fly.io** (most control, needs a `fly.toml`). All
three run the same Docker image (`Dockerfile` at the repo root) — nothing
platform-specific lives in the application code itself.

## Required environment variables (all platforms)

| Variable | Required | Notes |
|---|---|---|
| `TAVILY_API_KEY` | **Yes** | Free tier: 1,000 searches/month. https://tavily.com |
| `GROQ_API_KEY` | Yes, unless using Ollama | Free tier: 14,400 req/day on `llama-3.1-8b-instant`. https://console.groq.com |
| `GROQ_MODEL` | No | Default `llama-3.1-8b-instant` |
| `EMBED_MODEL` | No | Default `nomic-embed-text` — only matters if you're also running Ollama for embeddings |
| `AUTH_ENABLED` | No | `true`/`false`, default `false` |
| `JWT_SECRET` | Only if `AUTH_ENABLED=true` | Generate with `openssl rand -hex 32` |
| `DB_PATH`, `CHROMA_PATH`, `CACHE_DIR` | No | Point these at your platform's persistent-disk mount if it has one (see per-platform notes below) — otherwise they default to ephemeral container storage and history/cache/RAG index are lost on every redeploy |
| `CACHE_ENABLED` | No | `true`/`false`, default `true` |
| `LOG_FORMAT` | No | `text` (default) or `json` — use `json` on any platform with a log aggregator (all three below have one) |

None of the three platforms below run Ollama for you — either set
`GROQ_API_KEY` (simplest) or point `OLLAMA_BASE_URL` at a self-hosted
Ollama instance reachable from the platform's network.

## Render (recommended for a zero-config demo)

Render already has a `render.yaml` at the repo root (Render's
["Blueprint"](https://render.com/docs/blueprint-spec) format), so this is
the least manual of the three.

1. **Push to GitHub** (`git push` to a repo Render can see).
2. Go to https://render.com → **New** → **Blueprint** → connect the repo.
   Render reads `render.yaml` automatically and proposes the service.
3. Fill in the two `sync: false` secrets in the dashboard: `TAVILY_API_KEY`
   and `GROQ_API_KEY`. `JWT_SECRET` is auto-generated by Render (see
   `generateValue: true` in `render.yaml`).
4. Click **Apply**. First build takes ~3 minutes.

**Persistence:** Render's free tier has an ephemeral filesystem — `render.yaml`
currently points `DB_PATH`/`CHROMA_PATH` at `/tmp`, which is wiped on every
redeploy/restart. For persistent history across deploys, add a
[Render Disk](https://render.com/docs/disks) (paid tier) and change those
two paths to somewhere under its mount point.

**Recommended plan:** Free tier is fine for a portfolio demo; it spins
down after 15 minutes of inactivity and takes ~30s to wake on the next
request (Render's own behavior, not something this app controls) — worth
mentioning to anyone reviewing the live link so a cold start isn't
mistaken for a broken deploy.

## Railway

No blueprint file needed — Railway builds directly from the `Dockerfile`.

1. https://railway.app → **New Project** → **Deploy from GitHub repo**.
2. Railway detects the root `Dockerfile` automatically. If it also detects
   `backend/requirements.txt` and tries a Python buildpack instead, force
   Docker: **Settings → Build → Builder → Dockerfile**, path `Dockerfile`.
3. **Variables** tab → add `TAVILY_API_KEY` and `GROQ_API_KEY` (same values
   as above).
4. **Settings → Networking → Generate Domain** for a public URL.

**Persistence:** Railway offers [Volumes](https://docs.railway.app/reference/volumes) —
attach one mounted at `/app/data` and set `DB_PATH=/app/data/research.db`,
`CHROMA_PATH=/app/data/chroma_db`, `CACHE_DIR=/app/data/cache` in the
Variables tab (same paths the Docker Compose setup uses locally, for
consistency).

**Recommended plan:** Railway's free tier (Hobby) gives $5/month of usage
credit, which comfortably covers a low-traffic portfolio demo running the
Groq API path (no local model, minimal CPU).

## Fly.io

Most control of the three, and the only one that needs a config file this
repo doesn't already have — create `fly.toml` at the repo root:

```toml
app = "your-app-name"          # must be globally unique on Fly
primary_region = "iad"         # pick the region closest to you/your reviewers

[build]

[env]
  PORT = "8000"

[http_service]
  internal_port = 8000
  force_https = true
  auto_stop_machines = true
  auto_start_machines = true
  min_machines_running = 0

[[vm]]
  cpu_kind = "shared"
  cpus = 1
  memory_mb = 512

[mounts]
  source = "research_agent_data"
  destination = "/app/data"
```

Then:

```bash
fly launch --no-deploy          # detects the Dockerfile, creates the app, skips first deploy
fly volumes create research_agent_data --size 1   # 1 GB, matches [mounts] above
fly secrets set TAVILY_API_KEY=tvly-... GROQ_API_KEY=gsk_...
fly deploy
```

Set `DB_PATH=/app/data/research.db`, `CHROMA_PATH=/app/data/chroma_db`,
`CACHE_DIR=/app/data/cache` as additional `fly secrets set` values (or
plain `[env]` entries in `fly.toml` if you don't consider paths secret)
to persist to the mounted volume above.

**Recommended plan:** `shared-cpu-1x` / 512MB (as configured above) is
enough for the Groq API path; bump to 1GB+ if you plan to run the
`sentence-transformers` cross-encoder reranker or embed with a local
Ollama sidecar, both of which are meaningfully more memory-hungry.

## Getting the free API keys

**Groq** (LLM inference, replaces Ollama when you don't want to self-host
a model): https://console.groq.com → API Keys → Create Key. Free tier:
14,400 requests/day on `llama-3.1-8b-instant`.

**Tavily** (web search): https://tavily.com → sign up → the dashboard
shows your key immediately. Free tier: 1,000 searches/month.

## Local development (no Docker)

```bash
cd backend
pip install -r requirements-dev.txt   # or requirements.txt if you don't need lint/format tools
cp .env.example .env
# fill in TAVILY_API_KEY and either GROQ_API_KEY or a running local Ollama
uvicorn main:app --reload --port 8000
```

Or via the Makefile: `make dev && make run`.

## Local development with Docker

```bash
cp backend/.env.example backend/.env   # fill in the same values as above
docker compose up --build
open http://localhost:8000
```

Fully local (no external API keys for the model — Tavily is still
required for search) via the optional bundled Ollama service:

```bash
docker compose --profile local-llm up --build
docker compose exec ollama ollama pull llama3.2
docker compose exec ollama ollama pull nomic-embed-text
# then set OLLAMA_BASE_URL=http://ollama:11434 in backend/.env and restart
```

See `docker-compose.yml` for the full rationale on that networking note
("localhost" inside a container is not what you'd expect).
